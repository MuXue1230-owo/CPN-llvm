# cpnc

`cpnc` compiles one CPN26 root source unit to LLVM IR or an ordinary x86-64 Linux ELF object. Its C++ frontend constructs and verifies a module with the LLVM C++ API. The linked X86 target emits machine code in-process. It implements a subset of the [CPN26 standard](https://github.com/MuXue1230-owo/CPN/blob/CPN26/CPN26.md). The grammar reference is chapter 15. Chapter 21 §6.1 defines the requirements for a Core conformance claim.

## Build and run

Build from the LLVM checkout using its CMake, Ninja, Python and host C++ toolchain requirements.

```sh
cmake -S llvm -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DLLVM_TARGETS_TO_BUILD=X86
cmake --build build --target cpnc
build/bin/cpnc --std=CPN26 -c example.cpn -o example.o
cc example.o -o example
./example
```

For example, this program returns 42:

```cpn
generic<const i32 N>
i32 repeat(i32 value) {
    i32 sum;
    for (i32 n(0); n < N; ++n) {
        sum += value;
    }
    return sum;
}

i32 main() {
    return repeat<6>(7);
}
```

Use `--check` to bind and check the source or `-S` to emit textual IR. The built `cpnc` executable runs independently of Python and `llc`. Python generates immutable Unicode tables during the build and runs the test harness. Run `cmake --build build --target check-cpnc` on x86-64 Linux to verify the driver, IR, diagnostics and native execution.

The executable tests in [tests/test_cpnc.py](tests/test_cpnc.py) compile source, verify the IR with llvm-as, link the object with the host C compiler and check the result. Negative cases test parser rejection, binding rules, numeric domains, lifetime violations and initializer-skipping transfers.

Named `try_add`, `try_sub`, `try_mul`, and `try_div` on f32 and f64 report
operation-local IEEE flags and classify failures under `numeric.fp.result_mask`
and `numeric.fp.require_finite`. Their `checked_*` counterparts use the same
classification for NumericTrap. The explicit operations preserve the selected
rounding and sticky-state behavior in native execution and produce matching
result classifications during required constant evaluation. The `report_*`
forms expose the IEEE default value and local status in a `NumericReport<T>`
record with `value` and `status` fields.
`infinity<T>`, `quiet_nan<T>` and `signaling_nan<T>` construct binary32 and
binary64 encodings directly. The fallible NaN forms return `OutOfRange` with
empty IEEE status for an inadmissible payload.
Checked and Exact casts support f32, f64, fixed-width integers and platform
integers. Integer-destination truncation and saturation classify the exact
source value without generating IEEE events. Named casts accept the applicable
rounding modes and evaluate untyped real literals at their exact token value.

`std::Unit` supports its single value, nonthrowing transfer, and equality.
`std::ensure` applies the Boolean contract in all presets. `std::debug_assert`
uses the operation's `library.debug_assertions` setting, and `std::discard`
evaluates its operand once and retains its ordinary lifetime.

The minimal `std::Result` binding supports case queries, receiver-qualified
`value()` and `error()` access, and checked payloadless success for `Result<void,E>`.
Wrong-case checked access selects ContractTrap. `try_value()` and `try_error()`
return `WrongCase` on an inactive case and preserve payload references through
the corresponding const-qualified or mutable `std::Ref` on success. Mapping
adapters remain incomplete. Borrow checking follows reaching stores, selected
Result cases and supported branch joins to diagnose provable lifetime expiry
and publication of automatic borrows. Opaque writes and unresolved alias
paths limit that analysis.

### Outstanding Core coverage

* Function-type packs and packs in applied owner paths participate in deduction. Parameter and argument expansions require a visible unexpanded pack at the definition site, including in unused generic declarations. Unevaluated `decltype` operands participate in that binding and structural checking. Pack substitution handles expansions inside a query and queries instantiated once per outer pack element. An expansion can zip captured outer and local inner packs with equal lengths. Out-of-line generic member definitions bind both the owner and member parameters. Forwarding preserves the recorded argument category and qualification. Member syntax uses the receiver's declaration identity through `auto`, `decltype`, inherited members, conditional branches with agreeing receiver types, and calls with a known result type. Call results can be established by scalar and nominal reference bindings, receiver qualification and value category, direct generic deduction, and supported constraints. Generic definitions use declared requirements and enclosing `if constexpr` facts to resolve receiver types at the definition site. These facts include `SameType` chains, matching named structural requirements, resolved `consteval` predicate calls, and identical integer expressions, including bitwise operations and shifts, under the same numeric policy. The syntax binder preserves implications from established predicates when another predicate cannot yet be bound. If candidate results differ, their members can still establish the same interpretation of `<`. Ordinary source expressions can rebind a provisional generic member application after semantic lookup establishes a data field. Qualified static calls support chained aliases. Nested records, unions, enumerations, and aliases are indexed before layout. By-value fields and payloads complete their dependencies when needed, and pointer cycles retain their nominal identities. Constraint ordering uses propositional implication, including negation, disjunction and expansion of ordinary named requirements. Required Boolean evaluation errors remain blocking when the condition is reached. Generic bodies require separate structural evidence for dependent copy and move assignments with known operand categories. A possibly reserved field write retains its construction-plan check. Symbolic pack expansion, additional computed atom identities, and binding relational or member-template syntax on unresolved receivers in generic definitions remain partial.
  Plain sibling alias chains are resolved iteratively. Recursive resolution of other alias or layout dependencies reports resource exhaustion beyond 128 nested requests.
* Contract proof remains conservative. The proof CFG retains ordered signed and unsigned scalar relations across conditions, including short-circuit clauses and inherited override checks. Indirect callable types retain selected predicate-check effects and published borrow origins. Additional proof rules and opaque foreign lifetime contracts remain partial.
* Construction checks recognize immutable receiver aliases, conditional receiver views, local reaching pointer stores, and known layer and base arguments at direct and indirect calls. For a typed view that may designate the current construction layer, raw validation checks the actual designation before field access, calls that can access the layer, and whole-value copies. A proved access to a pending slot is a compile-time error. Interprocedural analysis also tracks a directly called function's borrow when its definition returns the unchanged pointer parameter. Access and initialization obey the published effect and construction-state contracts. Cleanup checks the reverse frontier and retains reconstructed slots' cleanup rank. A continuing Whole transfer rolls back completed construction prefixes for authored and aggregate constructors, array elements, memberwise copies, and tagged payloads. Cross-type and foreign alias paths remain partial.
* Complete objects and individually selected member and array-element extents support replacement, including by another fitting type. CPN-defined static `const` and `constexpr` objects retain their extent registration and original generation when an authorized operation ends and reuses their storage. Lowering diagnoses stale automatic designations whose prior generation is provable. Native control-flow checks diagnose direct static designations, direct accesses to original automatic and static subobjects, and saved generations in unaliased automatic pointer cells when every reaching path has retired the tracked generation. Subobject checks preserve the containing registration chain and its generation. A known call chain contributes to the retirement proof when every return ends the same automatic object through a reference or pointer parameter. The proof follows registrations and the live path’s reaching pointer assignments. For an indirect call with a proved set of targets, each target must retire the same generation. The frontend rejects construction of an automatic subobject proved live and storage operations through a view proved to outlast its containing generation. Runtime registration checks cover dynamically determined paths. Pointer provenance after untracked foreign writes or raw storage reinterpretation, whole-program escape checking, storage transfer, and allocator ownership remain incomplete.
* Constant evaluation supports generation-checked replacement of complete automatic objects, ordinary record members, array elements and active tagged payloads. Match keeps temporary payloads alive through arm cleanup. Authored tagged assignment preserves the fresh returned designation when it replaces a case. StorageView exposes capacity, alignment and identity in native and constant execution. Shared-base and closure lifetime checks remain partial. Required constant evaluation admits up to 64 nested activations before reporting resource exhaustion.
* Floating-point arithmetic covers f32 and f64. Direct numeric context calls expose MXCSR controls and sticky state. The setter admits nearest-even, toward-zero and the two directed rounding modes, the five IEEE trap flags and gradual subnormals. Other rounding and subnormal provider selections remain unavailable through the setter.
* The supported ABI is x86-64 System V for the tested scalar boundary. C++ ABI features, separate compilation, module imports, reflection, exceptions and concurrent execution are unimplemented capabilities.

### Target and invocation

The driver defaults to the Unicode identifier profile and the Debug integer policy. Use `--preset Release` for Native arithmetic, `--identifiers ascii` for the ASCII profile, or `--config path/to/cpn.config` to supply project configuration. A supplied project file must contain configuration declarations. The project and source use the same CPN26 configuration syntax. Custom uses the target's Checked integer and Strict floating defaults for unspecified operation policies. An untyped literal that needs its disabled default instead fails when materialized.

The default logical source path is relative to the project configuration's
directory, or to the working directory for a standalone build. An input
outside that directory defaults to its basename. `--logical-source PATH`
supplies a project-relative path explicitly. The root identity defaults to the
logical source path, with `--root-id ID` available for independently owned
roots with the same logical path. CPN-internal symbols have module-local
linkage. File-scope startup and shutdown use ELF constructors and destructors.
A project can explicitly select `static.schedule = serial`, `static.workers = 1`,
and a nonempty `static.identity_namespace`. The namespace defaults to the root
identity.

Native function and object symbols use the `cpn.v1` naming scheme. Each
dot-separated identity field is the lowercase hexadecimal encoding of its
exact UTF-8 bytes. Fields include the logical root, qualified declaration,
signature and applicable receiver qualifiers. Specialized declarations use
their canonical instance identities. Hosted `main` and C-bound declarations
retain their external names. `[[abi_symbol("...")]]` gives a C-bound function
or object an exact ELF symbol, and `[[abi_cc("sysv-amd64-2018.lp64")]]`
selects the target's supported calling convention explicitly.

The target has eight-bit bytes and 64-bit platform integers. Native addition, subtraction, multiplication and negation use modulo arithmetic. Exceptional Native division or remainder and invalid variable shift counts terminate through a target trap. Known invalid ordinary division or shift domains produce a source diagnostic. Direct object creation writes an ELF object suitable for the ordinary system linker.

The build compiles the Unicode tables into the driver. [utils/build_ucd.py](utils/build_ucd.py) reproduces them from the pinned Unicode 17.0.0 data files. Their license is included in [unicode/LICENSE.txt](unicode/LICENSE.txt).
